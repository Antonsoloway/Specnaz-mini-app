# Правила выпуска Royal CRM Mini App

## Обязательное правило истории изменений

Каждая новая версия Mini App выпускается только вместе с записью в разделе «История изменений».

Для версии `vX.Y.Z` одновременно должны быть выполнены все пункты:

1. Создан новый entrypoint `app-vXYZ.html` с номером новой версии.
2. Добавлена отдельная запись истории изменений для `vX.Y.Z` с кратким названием и фактическим списком изменений.
3. Новая запись истории стоит первой, предыдущие версии сохраняются без удаления.
4. Надпись «Текущая версия» и бейдж версии в приложении показывают один и тот же номер `vX.Y.Z`.
5. Новый entrypoint подключает файл истории этой же версии.
6. Старые entrypoint, если перенаправляют на актуальную версию, ОБЯЗАНЫ сохранять `location.hash` целиком. В hash Telegram передаёт launch-параметры (`tgWebAppData`), потеря hash ломает `Telegram.WebApp.initData` и авторизацию.
7. Для legacy-entrypoint запрещён `meta http-equiv="refresh"`: он может сработать раньше JavaScript и потерять Telegram launch hash. Использовать только JS `location.replace()` с переносом `search` и `hash`, либо оставлять старый entrypoint самостоятельным.
8. Корневой `index.html` и постоянный `app.html` подчиняются тем же правилам сохранения Telegram launch hash.
9. Перед публикацией проверяется не только версия и история, но и авторизация из Telegram: `Telegram.WebApp.initData` не пустой.
10. Перед публикацией проверяется сценарий `Участники → профиль → Назад`, чтобы новая раскладка и достижения не исчезали после восстановления списка.
11. Интерфейсные статусы и достижения участников связываются с карточкой только по raw Telegram ID; имя/@ник не используются как идентификатор.
12. Правый блок статусов/достижений участника строится вертикально. Для участника проекта «МАЯК» порядок текущих элементов сверху вниз: `Админ` (если есть) → ранг → `МАЯК`. Плашка `МАЯК` всегда самая нижняя.
13. Каждая новая ачивка должна переживать повторный render и возврат `Назад`; декоратор достижения обязан повторно применяться после восстановления списка.
14. Плашка версии обязана открывать объект `window.RoyalChangelog` самой новой загруженной версии. Старые обработчики истории не должны перехватывать открытие предыдущего журнала.
15. Постоянная Web App-точка входа — `app.html`. При каждом новом релизе меняется только её целевой `app-vXYZ.html`, сама внешняя ссылка остаётся постоянной.
16. После успешной авторизации участника Mini App должен обеспечить право @doveofpeace_bot писать пользователю. Для Telegram 6.9+ используется `WebApp.requestWriteAccess()`; при отказе вход считается незавершённым и показывается повторный запрос.
17. Служебное сообщение Telegram `write_access_allowed` обрабатывается как начало личного диалога с Голубем и должно приводить к отправке приветственного/подтверждающего сообщения от бота.
18. Счётчики команды в интерфейсе считаются из того же актуального набора участников, который реально выводится в составе; старые/вышедшие записи не могут увеличивать число участников, лидеров или помощников.
19. Если у команды нет фото, клиент не должен делать запрос изображения и не должен показывать битый `<img>` — используется штатная заглушка.
20. Поиск команд и участников должен быть быстрым и предсказуемым. Не допускаются комбинаторные переборы, расстояния опечаток и тяжёлое индексирование всего CRM на каждой введённой букве. Поддерживаются точное/частичное совпадение, кириллица/латиница, один детерминированный вариант чтения английского слова и небольшой явный словарь подтверждённых алиасов. Контрольные примеры: `Has ne dogonyat` ↔ `нас не догонят`, `XAOC` ↔ `хаос`, `TOPMO3OB HET` ↔ `тормозов нет`, `Mike` ↔ `майк`, `Xabib` ↔ `хабиб`, `JoyBand` ↔ `джойбанд`, `1BY` ↔ `1бу`.
21. Каждый релиз проверяется минимум на Android и iPhone/iPad в Telegram WebView. На iOS отдельно проверяются: `Назад`, карточка участника, участник → команда, @ник/ЛС, ранги, ачивки и внутренние кнопки.
22. Длинные списки должны иметь быстрые кнопки перехода вверх/вниз, не перекрывающие нижнюю навигацию и не сбрасывающие текущий поиск.
23. В шапке истории изменений блок `Помощь в разработке, тесты` содержит актуальный список: `@sfinks_spb`, `@O_Chaplygina`, `@Yanochka_2404`.
24. Поле поиска не должно заменяться/перерисовываться во время печати. При вводе фильтруются уже отрисованные карточки, чтобы Telegram WebView не терял пробелы, фокус и символы.
25. Запрещено вызывать `preventDefault()` или `stopImmediatePropagation()` для `input`, `beforeinput`, `compositionstart`, `compositionupdate`, `compositionend` в полях поиска. IME/экранная клавиатура полностью управляет вводом текста.
26. Если нужно убрать старые прямые обработчики поиска, поле после первоначального рендера заменяется на чистый `cloneNode(true)` один раз; дальше этот DOM-элемент сохраняется до ухода со страницы.
27. Android-поиск не должен зависеть от особенностей конкретной IME. Допускается лёгкое чтение `input.value` по таймеру только пока поле находится в фокусе, без вмешательства в composition/beforeinput.
28. Обычный кириллический запрос имеет приоритет обычного совпадения. Неоднозначные псевдорусские названия обрабатываются только через подтверждённые алиасы; если варианта нет в словаре, поиск не должен угадывать сотни комбинаций.
29. В новом entrypoint загружается только один актуальный поисковый модуль. Предыдущие поисковые hotfix/модули не подключаются одновременно.
30. Запрещён `prewarm` расширенного поискового индекса всех участников/команд в основном потоке. Поисковые ключи должны создаваться легко и лениво по уже отрисованным карточкам либо небольшими неблокирующими порциями.
31. На Android перед релизом отдельно проверяются: время появления клавиатуры после нажатия на поиск, свободный ввод нескольких букв подряд, пробелы, стирание, поиск без скрытия клавиатуры и отсутствие зависания первого символа.
32. Если поисковый модуль фильтрует карточки через атрибут `hidden`, стили приложения обязаны гарантировать `[hidden] { display:none !important; }` для карточек и empty-state; визуальное количество карточек должно совпадать со счётчиком найденных результатов.

## Текущая версия

На 17.08.2026 актуальная версия: `v0.5.47`.

Запись `v0.5.47 — Отображение результатов поиска` содержит:

- исправлен конфликт CSS со стандартным атрибутом `hidden`, из-за которого поиск v0.5.46 правильно считал результат, но неподходящие карточки оставались видимыми;
- логика Android-safe ввода и поиска v0.5.46 не изменялась;
- при результате `1 из 189` на экране теперь должна оставаться ровно одна найденная карточка;
- фикс применяется к спискам участников и команд;
- блок помощи в разработке и тестировании сохраняет `@sfinks_spb`, `@O_Chaplygina`, `@Yanochka_2404`.

Записи `v0.5.46`, `v0.5.45`, `v0.5.44`, `v0.5.43`, `v0.5.42`, `v0.5.41` и все предыдущие версии сохраняются в истории изменений без удаления.
