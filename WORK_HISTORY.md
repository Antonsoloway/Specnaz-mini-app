## 2026-08-18 — v0.5.59: исправлен постоянный кэш фото команд

**Симптом:** по Android screen recording аватарки участников после первого использования появлялись сразу, а фото команд при открытии карточки заметно догружались позже.

**Диагноз по фактическому коду и snapshot:**
- `media-persistent-cache-v0554.js` действительно использовал IndexedDB и для аватаров, и для фото команд;
- ключ аватара был стабильным: `avatarFileId`;
- ключ фото команды был ошибочно построен как `team:${photoUrl}`;
- Google Sheets выдаёт для одной и той же картинки команды временный `lh7-rt.googleusercontent.com/...` URL, который меняется между 5-минутными snapshot;
- подтверждение: у одной и той же `☀️ Has ne dogonyat / Royal Match` `photoUrl` в snapshot `20:03` и `20:28` различался при неизменном фото;
- из-за этого IndexedDB каждый новый snapshot видел как новую картинку и повторно качал её;
- дополнительно persistent loader перед disk-read снимал `src`, поэтому при disk miss/медленном чтении визуально появлялась пустая задержка.

**Исправлено во frontend:**
- `media-persistent-cache-v0554.js` поднят до внутреннего version **`0.5.54.1`**;
- постоянный ключ фото команды теперь строится по стабильной связке **`нормализованное название команды + игра`**;
- `photoUrl` используется только как source metadata, но не участвует в identity кэша;
- после загрузки snapshot приложение делает **disk-only prewarm** сохранённых team blobs из IndexedDB в `teamMemory`; сетевой prewarm запрещён и не добавлялся;
- уже кэшированная команда при повторном открытии должна получать фото синхронно из memory или быстро из disk;
- для реальной смены фото добавлен неблокирующий background refresh: после 30 минут с последней сетевой загрузки кэшированное фото показывается сразу, затем обновляется в фоне;
- общий TTL/cleanup 45 дней и общий лимит около 420 записей сохранены;
- `app-v0559.html` получил cache-bust `media-persistent-cache-v0554.js?v=20260818-2330`;
- changelog v0.5.59 дополнен фактической записью.

**Совместимость:** старые team-cache записи, созданные до этой правки, имеют ключ по временным URL и не могут надёжно мигрировать к team+game без знания их identity. Поэтому после обновления конкретную команду может понадобиться **один раз** загрузить из сети. После этого следующие открытия и следующие запуски Mini App используют стабильный ключ.

**Что не менялось:** Apps Script, Worker, snapshot schema и Google Sheets в этой правке не менялись; Cloud Shell не нужен.

**Smoke-test:** открыть команду с фото → вернуться → открыть её повторно (должно быть сразу); затем полностью закрыть Mini App, открыть снова и открыть ту же команду (должно подняться из IndexedDB без прежней сетевой задержки).

**Инвариант:** временный `team.photoUrl` Google Sheets нельзя использовать как ключ постоянного кэша. Identity team-photo cache = `название + игра`. Disk prewarm не превращать в массовую сетевую загрузку.

## 2026-08-18 — v0.5.59: фактическое имя `BbllllKA`, server alias подтверждён в live snapshot

**Задача:** после предыдущих попыток поиск `вышка` всё ещё не находил нужную команду Royal Kingdom.

**Точная причина:**
- реальное имя команды в CRM/snapshot: **`🗡 BbllllKA`**;
- после `Bb` идут четыре строчные латинские `l`;
- ранее имя было ошибочно прочитано как `BbIIIIKA`, поэтому server alias `'bbiiiika': ['вышка']` никогда не мог совпасть с фактическим объектом `bbllllka`;
- старый client overlay также использовал неправильное имя и не учитывал emoji `🗡` при exact-сравнении.

**Исправлено:**
- `search-aliases-v0559.js` исправлен на exact rule `BbllllKA + Royal Kingdom → вышка`;
- клиентская нормализация теперь убирает emoji/символы;
- при фактической мутации alias client overlay клонирует массивы snapshot, чтобы `search-hybrid-v0553.js` сбросил WeakMap haystack-кэш;
- `app-v0559.html` получил новый cache-bust клиента;
- через Cloud Shell повторно выполнен безопасный installer: backup → `clasp pull` → patch → syntax check → `clasp status` → `clasp push` → sync `apps-script-live/`;
- Unified Snapshot Writer поднят **`1.2.3 → 1.2.4`**;
- `searchIndexVersion` поднят **`1.1.2 → 1.1.3`**;
- ошибочный alias `bbiiiika` удалён;
- правильный alias: **`'bbllllka': ['вышка']`**.

**Подтверждено по фактическим данным:**
- `apps-script-live/25_MINIAPP_UNIFIED_SNAPSHOT.js`: writer `1.2.4`, search index `1.1.3`, alias `'bbllllka': ['вышка']`;
- новый `royal-crm-data/snapshot.json` опубликован `2026-08-18T20:03:09.308Z` (`23:03:09 UTC+3`);
- `snapshot.searchIndexVersion = 1.1.3`;
- `snapshot.unifiedSnapshotVersion = 1.2.4`;
- объект `🗡 BbllllKA / Royal Kingdom` содержит `searchKeys`: `bbllllka`, `ббллллка`, **`вышка`**, `vyshka`, ...;
- участники этой команды также получили `вышка`/`vyshka` в participant `searchKeys`.

**Инвариант:** фактическая identity этой команды — `🗡 BbllllKA / Royal Kingdom`. Не возвращать написание `BbIIIIKA`. Подтверждённый CRM-alias должен жить server-side в Unified Snapshot Writer; client overlay — только дополнительная страховка.

## 2026-08-18 — v0.5.59: SVG окончательно убран, крот встроен точным JPEG, заголовок каталога исправлен

**Задача:** после Android-скриншотов крот отображался с цветными/серыми полосами; верхний золотой заголовок требовалось заменить.

- обновлены cache-bust и changelog.

**Инвариант:** не возвращать SVG-wrapper, обычный `<img>` или внешний image-loader для крота.
