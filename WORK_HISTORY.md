## 2026-08-18 — Mini App v0.5.58: forward сверху, Back на прежнее место

**Задача:** страницы команд/участников иногда открывались в середине или внизу из-за наследования scroll-позиции.

**История:**
- v0.5.57 ввёл глобальный scroll-to-top, но ошибочно применил его также к Back;
- пользователь уточнил: новая страница должна открываться сверху, а `Назад` — возвращать туда, где пользователь остановился.

**Сделано в v0.5.58:**
- forward navigation всегда приводит новый экран к `scrollY=0`;
- `RoyalNav.back()` больше не оборачивается принудительным top;
- Back восстанавливает сохранённый `state.scrollY`;
- активен `navigation-scroll-top-v0558.js`;
- `app.html` направлен на `app-v0558.html`;
- GitHub Pages build `1157767246` подтверждён со status `built`.

**Инвариант:** вперед → верх; назад → точное прежнее место.

## 2026-08-17 — Поиск: найден и исправлен корневой дефект доставки searchKeys

**Симптом:** подтверждённые запросы `веном`, `сказка`, `мы русские`, `нервы в норме` не давали ожидаемых результатов, хотя часть ключей уже была в raw `snapshot.json`.

**Корневая причина:** Worker sanitizer в старой цепочке `/snapshot` пересобирал participant/team объекты и выбрасывал `searchKeys` и `searchIndexVersion`.

**Сделано:**
- добавлен Worker wrapper `worker/src/entry-v1110.js`, версия `1.11.1`;
- Worker после авторизованной sanitization безопасно возвращает `searchKeys` в уже очищенный snapshot;
- добавлено одно детерминированное pseudo-Cyrillic чтение, без fuzzy/edit-distance и без комбинационного взрыва;
- `worker/wrangler.toml` переключён на `src/entry-v1110.js`;
- frontend hybrid search сохраняет старую локальную семантику как fallback и использует server `searchKeys` только как дополнительный слой;
- контрольные алиасы включают `CKAZKA→сказка`, `BEHOM→веном`, `Mbl Pycckue→мы русские`, `HEPBbl/HEPBbI B HOPME→нервы в норме`.

**Инвариант:** итог поиска = локальный поиск ИЛИ `searchKeys`; server keys не имеют права уменьшать локальные результаты.
