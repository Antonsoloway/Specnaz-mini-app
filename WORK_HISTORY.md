## 2026-08-18 — v0.5.59: `BbIIIIKA → вышка` перенесён в live Apps Script, snapshot 1.1.2 подтверждён

**Задача:** после клиентского hotfix команда `BbIIIIKA` (Royal Kingdom) по-прежнему не находилась по запросу `вышка`.

**Корневая причина:**
- `search-aliases-v0559.js` добавлял `вышка` в `team.searchKeys` уже после загрузки snapshot;
- основной `search-hybrid-v0553.js` кэширует haystack карточек в `WeakMap`;
- поздняя мутация `searchKeys` не меняет ссылку массива snapshot и поэтому не гарантирует сброс уже построенного кэша;
- в фактическом live Unified Snapshot Writer серверного алиаса `BbIIIIKA → вышка` до этой работы не было.

**Правильное исправление:** алиас перенесён на серверную цепочку `Apps Script → searchKeys → snapshot.json → Worker → Mini App`.

**Выполнено через Cloud Shell:**
- создан и запущен `scripts/install-vyshka-search-v0559.sh`;
- перед patch выполнены backup, `clasp status` и `clasp pull` фактического live Apps Script;
- Unified Snapshot Writer поднят `1.2.2 → 1.2.3`;
- `searchIndexVersion` поднят `1.1.1 → 1.1.2`, чтобы изменение гарантированно вошло в новый dataHash/snapshot;
- в `MINIAPP_UNIFIED_SEARCH_ALIASES` добавлено `'bbiiiika': ['вышка']`;
- status bridge/schema 1.4.2 сохранены и проверены перед push;
- выполнены `node --check`, `clasp status` перед push, `clasp push`;
- после push выполнена синхронизация `apps-script-live/` обратно в GitHub.

**Ошибка установщика на скриншоте:**
- после успешного push финальный verifier упал с `/usr/bin/python3: Argument list too long`;
- причина: большой `snapshot.json` передавался Python через environment variable;
- это произошло **после** успешных `clasp push` и sync mirror и не отменяло deployment;
- установщик исправлен: snapshot теперь передаётся Python потоково через stdin pipe, без environment variable.

**Подтверждено:**
- `apps-script-live/25_MINIAPP_UNIFIED_SNAPSHOT.js` фактически содержит writer `1.2.3`, `searchIndexVersion=1.1.2` и `'bbiiiika': ['вышка']`;
- старый snapshot в `22:28:13` ещё имел `searchIndexVersion=1.1.1`, поэтому сразу после push приложение закономерно продолжало старое поведение;
- следующий штатный 5-минутный trigger опубликовал новый `snapshot.json` в `2026-08-18T19:33:12.518Z` (`22:33:12 UTC+3`) с `searchIndexVersion=1.1.2` и новым `dataHash`.

**Инвариант:** подтверждённые CRM-алиасы, которые нужны стабильно до построения клиентского кэша, должны находиться в server-side searchKeys Unified Snapshot Writer. Поздний client overlay не использовать как единственный источник такого алиаса.

**Осталось проверить в runtime:** после полного повторного открытия Mini App запрос `вышка` должен находить `BbIIIIKA` и в режиме `Все`, и при фильтре `РК`.

## 2026-08-18 — v0.5.59: SVG окончательно убран, крот встроен точным JPEG, заголовок каталога исправлен

**Задача:** после очередного Android-скриншота крот снова отображался с цветными/серыми полосами. Пользователь прислал чистое изображение крота и потребовал использовать его в точности, а верхний золотой заголовок заменить на `Команды принимающие участие в базе спецназа`.

**Диагноз:**
- предыдущий fix использовал `assets/specnaz-active-team-clean-v0559.svg` с вложенным raster-image;
- Telegram Android WebView продолжал артефактно декодировать/отрисовывать этот SVG-wrapper;
- проблема не была в позиционировании: и на странице команды, и на карточках активных команд искажения совпадали с проблемой source/render pipeline;
- для этого значка нужен прямой raster без SVG и без внешней image-loader цепочки.

**Сделано:**
- из присланного пользователем чистого изображения `1000238530.jpg` подготовлен квадратный 160×160 JPEG crop;
- JPEG встроен **напрямую в `active-teams-v0559.css`** как `data:image/jpeg;base64,...` в CSS custom property `--royal-specnaz-mole-v0559`;
- `.active-team-directory-button-v0559` на странице команды теперь использует этот data-asset как `background-image` с `background-size: cover`;
- `.team-card.active-team-gold-v0559::after` использует тот же data-asset, поэтому справа у всех активных команд отображается один и тот же крот;
- внешние JPG/SVG для текущего рендера крота больше не используются;
- создан `active-teams-title-v0559.js`: он наблюдает только за `#panel` и приводит заголовок каталога и `aria-label/title` кнопки к тексту `Команды принимающие участие в базе спецназа` после внутренних render;
- `app-v0559.html` подключает `active-teams-v0559.css?v=20260818-2208` и `active-teams-title-v0559.js?v=20260818-2208`;
- `changelog-v0559.js` обновлён и подключён с cache-bust `20260818-2208`;
- обновлены `CURRENT_STATE.md`, `WORK_HISTORY.md`, `RELEASE_RULES.md`.

**Подтверждено:** GitHub `main` содержит inline JPEG asset, новый title-hotfix и обновлённый entrypoint. Apps Script / Worker / snapshot в этой UI-правке не менялись. Фактическое отсутствие артефактов на Android Telegram WebView требует следующего пользовательского smoke-test.

**Инварианты:** для крота v0.5.59 не использовать SVG-wrapper, обычный `<img>` или внешний image-loader; активный source — встроенный JPEG data-asset в `active-teams-v0559.css`. Видимый заголовок каталога — `Команды принимающие участие в базе спецназа`.
