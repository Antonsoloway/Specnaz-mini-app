# 2026-08-21 — Process diagnostic: rules for future work sessions

## Причина записи
Зафиксировать ошибку рабочего процесса при восстановлении задачи Royal CRM / «Таблица ЧП», чтобы следующие чаты не повторяли её.

## Обнаруженные проблемы
- Нельзя считать задачу выполненной без фактического цикла: открыть код → изменить → проверить → commit → собрать preview.
- Нельзя опираться только на CURRENT_STATE.md. Документация является ориентиром, а фактический GitHub/runtime имеет приоритет.
- Нельзя предполагать пути файлов по памяти или старым контекстам. Перед изменением обязательно получить реальное дерево репозитория и открыть фактический файл.
- Нельзя заменять выполнение промежуточными отчётами о планах.
- Нельзя объявлять готовую сборку, если нет фактического commit и проверяемого результата.

## Обязательный протокол
1. Сначала читать START_HERE.md, CURRENT_STATE.md и последние записи WORK_HISTORY.md.
2. Затем сверять фактические файлы GitHub.
3. При расхождении документации и кода — фиксировать расхождение, не делать предположений.
4. Изменять только найденные реальные файлы.
5. После изменения:
   - проверка кода;
   - commit;
   - обновление CURRENT_STATE.md;
   - обновление WORK_HISTORY.md;
   - ссылка на готовую preview-сборку.

## Главный принцип
Результат важнее отчётов. Если нет готового изменения и проверяемой версии — работа не считается выполненной.
