# 2026-09-06 — v0.6.1 admin journal newest-first ordering

## Симптом

В админ-режиме на вкладке «Журнал» записи разных источников отображались в смешанном порядке: более старые события могли оказаться выше более новых. На device smoke 06.09.2026 в верхней части списка была видна запись от 30.08, хотя журнал уже содержал более свежие изменения.

## Причина

`admin-journal-v0600.js` отображал `adminData.journal.rows` строго в том порядке, в котором массив пришёл с backend. Worker v1.41.0 уже пытается объединять и сортировать обычный journal с achievement-journal, но UI не имел собственного инварианта порядка. Любой fallback/base response, stale merge или источник с иным порядком снова приводил к перемешиванию.

## Исправление

- Добавлен v0.6.1-only модуль `admin-journal-order-v061.js` (`0.6.1-journal-order.1`).
- Перед каждым `RoyalAdminJournalV0600.render(rows)` журнал теперь копируется и стабильно сортируется по фактическому времени: самые свежие сверху, самые старые снизу.
- Приоритет времени: `occurredAtIso` → `at` → `timestamp` → `createdAt` → `updatedAt`.
- Поддерживаются ISO/RFC timestamps, legacy `DD.MM.YYYY HH:mm[:ss]` и defensive `YYYY-MM-DD HH:mm[:ss]` без timezone; legacy значения трактуются как Europe/Moscow (UTC+3), как и существующий журнал.
- При одинаковом времени сохраняется исходный порядок; записи без распознаваемой даты уходят после датированных, а не перемешиваются с ними.
- Исправление выполняется только на presentation layer и не изменяет исходные journal rows, фильтры, поиск, пагинацию, Apps Script или Google Sheets.

## История изменений

Добавлен `changelog-v061-latest.js`: он дописывает это исправление в секцию «Последние изменения» карточки v0.6.1. Модуль подключается сразу после `changelog-v0601.js`, поэтому новые frontend hotfix можно фиксировать без рассинхронизации основной истории.

## Release

- Cache/release marker: `20260906-v061-journal-order1`.
- `app.html` → `app-v0601.html` → `app-v0600.html` обновлены на новый marker.
- `app-v0600.html` загружает `admin-journal-order-v061.js` сразу после `admin-journal-v0600.js`, до `admin-v0600.js`.
- Worker, Apps Script, Google Sheets и private data schema не менялись.

## Acceptance

Полностью закрыть Mini App в Telegram, открыть заново → Админ режим → Журнал. Верхняя карточка должна иметь самое позднее время среди всех записей; при прокрутке вниз даты должны только уменьшаться. Поиск и фильтры должны сохранять этот newest-first порядок.
