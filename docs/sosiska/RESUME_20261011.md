# Агент «Сосиска» — модуль ЧП, этап 1

## Состояние

Исходная ветка Mini App: main, commit 5fef716b0d526a5e8248c12bb15361e321a4c3f3. Работа сохранена отдельно в sosiska-miniapp-stage1-20261011. Main и production не изменены. Нельзя считать модуль подключённым только потому, что код и тесты готовы.

## Реализовано

- Администраторская кнопка «Агент Сосиска» на главном экране ЧП.
- POST /admin-agent: общая с существующей админкой проверка подписанной сессии и актуальной роли Telegram. Ключ агента хранится только в секретах Worker. Запросы с чужим Origin, неподдерживаемыми полями/операциями и телом >4096 байт отклоняются.
- Гибридный поиск: название и его русские визуальные/транслитерированные варианты плюс WorldTeams/LocalTeams. Частичная недоступность источников показывается как предупреждение. Дедупликация по точному строковому int64 TeamId.
- Результаты по четыре карточки: описание и лидер загружаются последовательно, чтобы не переполнить очередь облачной игровой сессии. Следующие карточки доступны через пагинацию.
- Полный состав, роли, уровни, короны, помощь, раскрываемые остальные серверные поля команды и участников.
- Ручное сохранение снимка; история страницами по пять записей; сравнения, входы/выходы, роли и числовые дельты. Отрицательные дельты не интерпретируются автоматически как потеря прогресса.
- Включение/изменение интервала 60–10080 минут только по явному нажатию администратора. Остановка отслеживания не удаляет историю. Просмотр, поиск и ИИ-анализ не включают watches и не создают снимков.
- ИИ-анализ последних двух сохранённых снимков по кнопке. Сервер сам читает снимки из агента; браузер не может подменить данные анализа. Groq GPT OSS 120B, отдельный SOSISKA_GROQ_KEY, модель можно переключить на GPT OSS 20B серверной переменной SOSISKA_GROQ_MODEL. Есть даты, номера исходных снимков и название модели. Отсутствующие снимки, секрет или полный ответ не заменяются выдуманным анализом.
- HTML игровых имён/описаний/анализа экранируется. Поздний ответ после смены экрана или сессии не возвращает прежние данные на экран.
- Новый entry-v1420 делегирует все прежние маршруты entry-v1410. В entry-v1380 только экспортирована существующая authorizeAdmin, её поведение не изменено.
- У /admin-agent отдельное окно transport 120 секунд; нет fallback в GAS и автоматического повтора watch/capture.

## Проверки

22 новых теста API/авторизации/UI/ИИ и 22 существующих теста admin-data/transport проходят локально. JavaScript syntax и bundle esbuild проходят; bundle ~290 KB. GitHub workflow Sosiska module выполняет эти же проверки и сборку.

Старые worker-background-music-v0600 / worker-snapshot-cache-v0600 тесты отдельно проверены: часть утверждений устарела уже на исходном main (ожидают entry-v1290 вместо исходного v1410 и старую константу cache), у cache VM fixture отсутствует setTimeout. Эти старые тесты не исправлялись в данной задаче; полный исторический набор не объявлять зелёным.

## Подключение: реальное препятствие

Проверка текущего Wrangler OAuth через Cloudflare API дала HTTP 200, один доступный аккаунт 62c513d37c8b15db448b263dfb7d2dee. В нём есть specnaz-royal-match-agent-stage1, но нет royal-crm-miniapp-api. Поэтому текущий доступ не позволяет добавить секреты и развернуть Worker ЧП (его адрес royal-crm-miniapp-api.tropical-spoon.workers.dev).

Перед rollout нужны доступ к аккаунту существующего Worker ЧП и серверные секреты:

- RM_AGENT_API_KEY: уже существующий ключ облачного агента, переносить напрямую между приватными хранилищами; не выводить и не помещать в GitHub/frontend.
- SOSISKA_GROQ_KEY: отдельный ключ анализа. Не менять конфигурации Голубя/Толика и не объявлять анализ подключённым без живой проверки.
- Существующие BOT_TOKEN, SESSION_SECRET, GITHUB_TOKEN и vars сохраняются.

Облачный игровой endpoint: https://specnaz-royal-match-agent-stage1.soloway3852.workers.dev. Контракт /v1/invoke и /v1/monitor соответствует развёрнутому исходнику b2045df061af593d27bb2543c259ea0b6ae69d6e. Агент и его история не менялись этим этапом.

## Ограничения текущего этапа

- ID эмблемы/аватаров и профильные данные доступны, графические игровые assets ещё не сопоставлены. Не выдавать числовой ID за готовую картинку.
- ИИ анализирует последние два снимка; произвольный выбор периода ещё не реализован.
- Распознавание русских вариантов общее, не гарантирует все творческие смешанные написания.
- Score и сумма уровней/корон не являются подтверждёнными очками событий.
- Сервисный аккаунт не играет/не входит в лигу, его короны не нужны. Изменение уровня отложено пользователем. Не изменять уровень/прогресс и не включать тестовые команды в мониторинг.
- Автономная игровая сессия работает в облаке; естественное истечение токена не было наблюдено. Восстановление при имитированном отказе проверено ранее. Это не блокирует реализацию интерфейса.
