## Реализация

- «Анализ всей истории всех отслеживаемых команд» запускает фоновую задачу. Дополнительно доступен анализ всей истории открытой команды.
- Команды берутся из актуального watch list, enabled=true. Анализ не создаёт watches, снимки и игровые запросы: читает только уже сохранённую историю через /v1/monitor.
- Каждая команда читается страницами до sequence=1. Нет ограничения первыми 2/20/100 снимками. При первом чтении фиксируется headSequence; новые снимки не смешиваются с уже начатым отчётом. В отчётах видны точные период, количество и охват по каждой команде.
- Пропуск sequence, неполная страница, чужой TeamId или отсутствие первого baseline прерывают задачу с ошибкой; частичная история не объявляется полной.
- Первый baseline и ВСЕ сохранённые изменения превращаются в ряд: значения команды/игроков, входы/выходы, роли и все изменившиеся поля. Повторение неизменных сырых полей не требуется. Неизвестные дополнительные поля не выбрасываются. Строки делятся на части без потери байтов, включая длинные значения.
- GPT получает все части; промежуточные анализы последовательно объединяются в итог команды и общий сравнительный отчёт всех выбранных команд. Промежуточные тексты — резюме, а не точная замена исходных данных; исходная история сохраняется у агента, числовая динамика доступна отдельно.
- Для каждого снимка сохраняется точная числовая точка с уровнями/коронами/помощью/составом и changes. UI показывает динамику страницами, включая показатели и дельты игроков, а не только общий текст ИИ. Пагинация интерфейса не ограничивает охват анализа.
- SQLite Durable Object SOSISKA_ANALYSIS / SosiskaAnalysisJobs хранит задачу, курсоры, части, промежуточные и итоговые отчёты. Alarms выполняют по одному этапу; восстановительный alarm ставится до внешнего I/O. Закрытие приложения/холодный старт не обнуляют обработку. Временные ошибки повторяются с задержкой; после пяти неудач задача помечается failed, а не done.
- Активный анализ повторно не дублируется; другой scope не заменяет активную задачу. Завершённые отчёты сохраняются. Открытие экрана читает статус без нового анализа; обновление статуса не перерисовывает ввод пользователя.
- Вся работа с задачами проходит через проверку админской сессии /admin-agent. Данные анализа сервер читает сам; браузер не может прислать поддельные снимки. Секреты не попадают в ответы/frontend/GitHub.
- Исправлен runtime-дефект предыдущего этапа: Workers не поддерживает redirect:'error'. Для приватных agent/Groq calls теперь redirect:'manual'; ответы перенаправления не принимаются и ключи не пересылаются на другой хост.

## Контракт /admin-agent

- analysis, необязательный teamId: старт всех отслеживаемых или одной команды.
- analysisStatus, необязательный jobId: сохранённый статус/отчёт; без ID — последняя активная/завершённая задача.
- analysisTimeline, jobId + teamId, необязательные limit (1–20), before: точная динамика с cursor.
- Остальные операции поиска, состава, watch/unwatch, capture/history сохранены.
